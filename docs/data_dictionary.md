## 8. Suspicious values

- **Category contamination (most important finding):** `二级类目` has only 2 values — 78/106 rows (73.6%) are `义齿修复材料` (denture repair material), only 28/106 (26.4%) are `义齿基托` (denture base — the stated pilot category). This directly confirms the purification risk described in the project brief: a keyword-based export is not category-pure, even at the "secondary category" level supplied by SellerSprite itself.
- `小类目` includes 3 rows that read as clearly non-dental: `Screwdriver Sets`, `Screwdriver Bit Holders`, `Jewelry Making Wax Molding Materials` — likely false positives from generic term overlap (e.g. "wax", "bit").
- One `小类目` value contains a raw `_x000D_` escape artifact: `"Emergency Dental Care Products_x000D_\nDenture Adhesives"` — an unparsed carriage-return from the source export; needs sanitizing before use, not a meaningful double-category label.
- `上架时间` ("listing date"): stored as float in **0.30–0.88**. This is not a valid Excel date serial (those are >40,000 for 2020s dates) and does not resolve to any obviously sensible date or duration. **Meaning is unknown — not assumed to be a date.** Needs clarification from SellerSprite documentation or the user before any use.
- `子体销量` / `子体销售额`: 70.75% / 71.7% missing. Plausible causes: SellerSprite may only populate these above a sales threshold, or they may apply only to certain listing types. **Not assumed to mean zero sales** — treating a blank as 0 would need explicit justification.
- Revenue consistency check: where both are populated, `子体销售额($) / 子体销量` matches `价格($)` almost exactly (diff = $0.00) for most rows, with a few larger mismatches (e.g. `B0F8VRJWC7`: −$29.47; `B0H7HF45WN`: +$5.29). Suggests revenue is largely `price × sales` rather than an independent measurement, and that price may have moved between when sales were captured and when price was captured. Caveat for any revenue calculation, not a data-entry error.
- `产品经理`: constant across all 106 rows (`覃柳敏`). Internal company metadata, not Amazon marketplace data — carries no analytical signal.
- `包装重量` / `包装尺寸`: stored as text with embedded units (`"290.30 g"`, `"15.24 x 7.87 x 3.30 cm"`), not separate numeric fields — needs parsing before numeric use.

## 9. Likely identifiers

- **ASIN** — the natural listing identifier. 105/106 unique (1 duplicate pair, see §6). Maps to `listings.asin`, but uniqueness is **not** guaranteed in the raw export as-is.
- 商品详情页链接 (product URL) — derived directly from ASIN (`amazon.com/dp/<ASIN>`); redundant as an identifier, used as `listings.url`.

## 10. Likely sales/revenue fields

- 子体销量 → candidate for `listings.monthly_sales` (period assumed monthly per SellerSprite convention — **not confirmed in this file**, flagged as an assumption).
- 子体销售额($) → candidate for `listings.monthly_revenue` (same period assumption).
- 价格($) → `listings.price`.
- FBA($) → per-unit FBA fulfillment fee. Not present in the current DB schema — candidate for a future column if margin analysis is needed later; not required now.

## 11. Likely product-description fields

- 商品标题 → `listings.title`.
- 品牌 → `listings.brand`.
- 二级类目 → coarse category signal (2 values only). Candidate for `categories.parent_category` or a purification filter field — **not** `leaf_category` (too coarse, and shown above to be impure).
- 小类目 → finer category / product-type signal (18 values). Best available candidate for `products.product_type` in a later milestone, and the most useful field for detecting non-dental contamination.
- 包装重量（单位换算）, 包装尺寸（单位换算）, 包装尺寸分段 → physical-attribute fields, useful later for product matching/clustering; not part of the current `listings` schema.

## 12. Likely review/rating fields

- **No review-count column exists in this export.** `listings.review_count` (per the DB schema) has no source field here — must come from another export/source, or remain NULL. Flagged as a schema/data gap.
